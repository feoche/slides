# Slidev Talks

François Eoche's talks, written in [Slidev](https://sli.dev/) (Markdown + Vue) with a shared custom theme
(`slidev-theme-feoche`). Every deck follows the same structure so they look, behave and export the same way.

## Requirements

- Node.js 20+ and **pnpm** (`pnpm install` once at the repo root)
- Optional: [Pandoc](https://pandoc.org/installing.html) (+ a LaTeX engine for PDF) for `export:docs`
- Optional: `playwright-chromium` (already a devDependency) for `pnpm export`

## Quick start

Everything you edit lives in **`talks/`**, sorted into `pro/` (work) and `misc/` (side projects):

```bash
pnpm install
npm run new -- pro/my-talk "My Talk Title"   # creates talks/pro/my-talk/
pnpm dev my-talk                             # serve it on http://localhost:3030
```

- `pnpm dev` alone shows a picker of all talks; a talk can be named by its folder (`bookmarklets`) or full path
  (`pro/bookmarklets`).
- Edit `talks/<pro|misc>/<slug>/slides.md`; drop images in the talk's `img/` folder.
- You never need to open `src/` to write a talk.
- Rules every talk follows (structure, headings, layouts): see [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Repository layout

```
talks/                         ← YOUR TALKS — the only folder you need for content
├── slides.example.md          ← reference deck copied by `npm run new` (don't edit for a talk)
├── home.yaml                  ← talks shown on the website's home page, in order
├── pro/<slug>/                ← work talks
└── misc/<slug>/               ← side-project talks
src/                           ← tooling, rarely touched
├── common/                    ← slides shared by every talk (intro, disclaimer, toc, end)
│   ├── showcase/              ← every layout & template in one deck (`pnpm dev showcase`)
│   └── media-demo/            ← media layouts with video / YouTube (`pnpm dev media-demo`)
├── theme/                     ← slidev-theme-feoche (layouts, components, styles/tokens.css)
├── templates/                 ← one snippet per layout, to copy slides from
└── _templates/                ← Pandoc export templates (default-meta.yaml, handout.html/css)
scripts/                       ← new-talk, serve-boards, build-boards, export-board, export-docs
```

## Talk structure

Each talk is a folder `talks/<pro|misc>/<slug>/` containing:

| Path         | Purpose                                                                    |
|--------------|----------------------------------------------------------------------------|
| `slides.md`  | The deck. Only files named `slides.md` are picked up by `pnpm dev`.        |
| `outline.md` | Optional: abstract and chapter list, written before the deck exists.       |
| `meta.yaml`  | Pandoc metadata (title, author, lang) for `npm run export:docs`.          |
| `img/`       | Images and videos, referenced from slides as `/file.jpg` (leading `/`).   |
| `export/`    | Generated by `export:docs` (git-ignored).                                  |

A talk that only has an `outline.md` is an idea: run `npm run new -- <pro|misc>/<slug> "Title"` to add its deck next
to the outline.

### Slide order

Every deck follows this skeleton (see `talks/slides.example.md`):

1. **Headmatter + cover** — `layout: cover`, title, author, date, QR code to `url` (see [QR codes](#qr-codes))
2. **`src/common/intro.md`** — speaker presentation
3. **`src/common/disclaimer.md`** — the "speaker bias" disclaimer
4. **`src/common/toc.md`** — table of contents (built from `# h1` titles)
5. **Content** — one `layout: section` slide (`# h1`) per chapter, followed by its content slides (`## h2`)
6. **Closing** — `layout: center` slide (thanks / questions / teaser)
7. **`src/common/end.md`** — contacts and feedback QR code (set `qrCode:` on the `src:` slide to change it;
   defaults to `qr:https://francoiseoche.fr`)

Shared slides are included with a `src:` slide, using a path relative to the deck:

```md
---
src: ../../../src/common/intro.md
---
```

### Headmatter

The first frontmatter block configures the whole deck:

| Key                  | Use                                                                  |
|----------------------|----------------------------------------------------------------------|
| `title`, `info`      | Title and description (also used for SEO, the cover and the [website](#website) cards) |
| `url`                | Public URL of the talk — rendered as the cover QR code               |
| `date`               | `YYYY-MM-DD`, displayed on the cover (`$frontmatter.date`)           |
| `keywords`           | Comma-separated: exported PDF metadata and [website](#website) card badges |
| `summary`, `event`   | Optional: short summary and event of the talk, on its [website](#website) card |
| `duration`           | Planned talk length, e.g. `20min`                                    |
| `colorSchema`        | `auto`, `light` or `dark`                                            |
| `themeConfig`        | Optional color overrides, see [Colors](#colors)                      |
| `htmlAttrs.lang`     | Deck language (`fr` by default)                                      |
| `seoMeta`            | Open Graph / Twitter tags                                            |
| `theme`              | Relative path to `src/theme` (`../../../src/theme` for `<pro\|misc>/<slug>`) |
| `addons`             | `slidev-addon-qrcode` (optional: QR codes use `<MediaEl src="qr:…"/>`) |

The author name comes from the theme config (`$slidev.configs.author`).

### Colors

Every theme color can be overridden per talk with `themeConfig` in the headmatter. All keys are optional;
values are any CSS color. Slidev exposes each key as a `--slidev-theme-<key>` CSS variable, which
`src/theme/styles/tokens.css` reads with the theme default as fallback.

```yaml
themeConfig:
  primary: "#0050d7"
  secondary: "#00185e"
  light: "#ffffff"
  dark-link: "#bef1ff"
```

**Palette** — base colors, used by both color schemes and by layouts/components directly:

| Key         | Default   | Used for                                                               |
|-------------|-----------|------------------------------------------------------------------------|
| `primary`   | `#00574a` | Titles and highlight background (light), highlight background (dark), Slidev built-ins |
| `secondary` | `#003D34` | Text (light), background (dark), progress bar, window/end frames       |
| `light`     | `#f8faf9` | Background (light), titles and text (dark)                             |
| `link`      | `#3ab9d5` | Links                                                                  |

**Roles** — fine-grained overrides, taking precedence over the palette. Each key applies to the light scheme;
prefix it with `dark-` (`dark-background`, `dark-title`…) to target the dark scheme. Light and dark keys are
independent: a light override never leaks into the dark scheme.

| Key                           | Light default           | Dark default             |
|-------------------------------|-------------------------|--------------------------|
| `background`                  | `light`                 | `secondary`              |
| `title`                       | `primary`               | `light`                  |
| `text`                        | `secondary`             | `light`                  |
| `text-shadow`                 | `secondary`             | `#666`                   |
| `highlight-background`        | `primary`               | `primary`                |
| `highlight-title`             | `light`                 | `light`                  |
| `highlight-text`              | `light`                 | `light`                  |
| `highlight-text-shadow`       | `secondary`             | `secondary`              |
| `highlight-link`              | `link`                  | `dark-link`              |
| `dark-link` (dark only)       | —                       | `link`                   |

Highlight colors apply to the layouts listed in `src/theme/layoutHelper.ts` (`shouldHighlightLayout`).

### Conventions

- **Headings**: `#` only on cover and section slides (they feed the TOC); `##` for slide titles, `###` for subtitles.
  A `###` is a subtitle only when written on the line right under the title; with a blank line in between,
  it is a regular heading.
- **One idea per slide**; prefer short bullet points.
- **Speaker notes** go in a trailing HTML comment: `<!-- ... -->`.
- **Per-slide styles**: a `<style>` block inside the slide is scoped to that slide.
- **Assets** live in the deck's `img/` (set as Vite's public dir in `src/theme/vite.config.ts`), never in another deck.
- **Images in slide content** use a bound `src`: `<img :src="'/file.jpg'" alt="…">`. Markdown `![](/file.jpg)` fails
  the build; `media: /file.jpg` in frontmatter works as is.
- Run `pnpm prettier --write "talks/**/*.md"` before committing.

## Layouts

Set with `layout:` in a slide's frontmatter; ready-to-copy snippets are in `src/templates/`. Properties are
frontmatter keys of the slide; slots are `::name::` lines in its content, the default slot being everything before
the first named slot.

### Shared behavior

- **Footer**: author — title, page number and progress bar, at the bottom of every layout except `cover`, `intro`,
  `disclaimer` and `end`. Layouts holding media stop above it (`--footer-height`, 2.5rem).
- **Highlight colors**: `cover`, `end`, `fact`, `intro` and `section` use the `highlight-*` colors of `themeConfig`
  instead of the regular ones; the footer drops its title there.
- **Asset paths** (`media`, `image`): files of the deck's `img/`. `/file.jpg`, `./file.jpg` and `file.jpg` are
  equivalent; absolute URLs (`https:`, `data:`, `qr:`…) are kept as is.

### Title and text layouts

#### `cover`

First slide of a deck. The content is vertically centered and a `###` under the title is enlarged. A bar at the
bottom shows the date on the left and the QR code slot on the right. No footer, highlight colors.

- `date` (headmatter): shown as DD/MM/YYYY; today's date when missing, the raw value when it isn't a date.
- `::qr-code::`: usually `<MediaEl :src="'qr:' + $frontmatter.url"/>` (or an image), shown as a 12.5rem square.
  Hidden when empty.

```md
---
layout: cover
date: 2026-11-19
---

# {{ $frontmatter.title }}
### {{ $slidev.configs.author }}

::qr-code::
<MediaEl :src="'qr:' + $frontmatter.url"/>
```

#### `intro`

Speaker presentation. Large `##` (the name), a `###` right under it, a round 10rem picture in the top-right corner;
lists are spaced out and links are pushed to the right of their line. No footer, highlight colors.

- `image`: the picture, a file or a color (`#…` / `rgb(…)`). No picture when missing.
- `backgroundSize`: how the picture fills the circle (default `cover`).

#### `disclaimer`

Black slide with white text: the `##` is red, uppercase and centered, paragraphs are cream. No footer.

#### `section`

Chapter title: the `#` is vertically centered (and feeds the table of contents). Highlight colors.

#### `default`

Regular content, stacked from the top with a 1rem gap. Used when `layout` is not set.

#### `center`

Content centered horizontally and vertically, text centered.

#### `fact`

Striking statement: centered content, a huge bold `##` (a number, a word) and the lines under it as a caption.
Highlight colors.

#### `quote`

Content centered in the slide; a blockquote gets padding and a filled background (gray in light mode, green in dark
mode).

#### `full`

Content filling the whole slide, without padding.

#### `none`

The bare content: no wrapper, no padding, no styles.

#### `end`

Last slide, as a bento grid of cards (5 columns × 3 rows). No footer, highlight colors.

- default slot: above the grid.
- `::main::`: the large card on the left (3 columns), under a round 10rem picture. A list is laid out as a centered
  row (social links); `#####` titles and links are 2.25rem.
- `::feedback::`: the top-right card.
- `::qr-code::`: the card under it (2 rows); a `<MediaEl>` in it fills the space left under its label.
- `image`, `backgroundSize`: the round picture, as for `intro`.

Decks use the shared `src/common/end.md`, whose QR code is set by `qrCode` on the `src:` slide.

### Grid layouts

Columns are flex columns with a 1rem gap between their elements. Every grid layout accepts:

- `class`: classes added to **each column/cell** (not to the slide), e.g. `class: items-center`.
- `layoutClass`: classes added to the layout root, e.g. `layoutClass: text-sm`.

#### `two-cols`

Two equal columns, 2rem apart.

- default slot and `::left::`: left column (both can be used, the default slot comes first).
- `::right::`: right column.

#### `two-cols-header`

A full-width header, two equal columns, then a full-width row stuck to the bottom of the slide.

- default slot: header.
- `::left::`, `::right::`: the columns.
- `::bottom::`: the bottom row (sources, a conclusion…).

#### `two-thirds`

Two columns, the left one twice as wide (`2fr 1fr`), 2rem apart.

- default slot and `::left::`: wide column; `::right::`: narrow column.
- `reverse: true`: widths become `1fr 2fr`. Only the widths change: `::left::` stays on the left, now narrow.

#### `two-thirds-header`

`two-cols-header` with `2fr 1fr` columns.

- default slot: header; `::left::` (wide), `::right::` (narrow); `::bottom::`: bottom row.
- `reverse: true`: widths become `1fr 2fr`, as for `two-thirds`.

#### `three-cols`

Three columns, the center one twice as wide (`1fr 2fr 1fr`), 2rem apart, then a full-width row stuck to the bottom.
No header slot: put the title in `::left::` or use `three-cols-header`.

- `::left::`, `::center::`, `::right::`: the columns.
- `::bottom::`: the bottom row.
- `layoutClass: centered`: centers each column's content horizontally and vertically, text centered.

#### `three-cols-header`

A full-width header, three equal columns, then a full-width row stuck to the bottom.

- default slot: header.
- `::left::`, `::center::`, `::right::`: the columns.
- `::bottom::`: the bottom row.

#### `three-rows`

Three equal rows, 2rem apart, each one's content at the top of its row (vertically centered in exports).

- `::top::`, `::center::`, `::bottom::`: the rows.

#### `six-cells-header`

A full-width header above a grid of 2 rows × 3 equal cells.

- default slot: header.
- `::top-left::`, `::top-center::`, `::top-right::`, `::bottom-left::`, `::bottom-center::`, `::bottom-right::`: the
  cells.

### Media layouts

#### `media`

The content (a title…) on top, the media below it, filling the remaining height above the footer with its aspect
ratio kept. With `window: true`, the frame is centered instead.

#### `media-left` / `media-right`

The media in a column (at least 375px wide) on the left / right, the content in the other column.

- `class`: classes added to the content column.
- `backgroundSize`: an image is drawn as the column's background, sized with it: default `cover` (cropped to fill)
  for `media-left`, `contain` (whole image) for `media-right`.

#### `media-full`

The media over the whole slide, above the footer. An image becomes the slide's background (`backgroundSize`,
default `contain`) and the content is drawn over it; any other media is shown after the content.

#### Media properties

Shared by the four media layouts:

- `media`: the source; its kind is detected from it:
  - image: `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.avif`;
  - video: `.mp4`, `.webm`, `.ogg`, `.mov`, played with controls;
  - YouTube: a `youtube.com` / `youtu.be` URL, embedded (a `t=` / `start=` timestamp is kept);
  - QR code: `qr:` followed by the data to encode (`qr:https://example.com`), drawn in the title color;
  - anything else: a web page, in an iframe.
- `objectFit`: `object-fit` of an image or a video (default `contain`; `cover` crops it to fill).
- `window: true`: shows the media inside a frame:
  - `type`: `desktop` (a browser window) or `mobile` (a phone). Detected from an image's ratio when missing
    (portrait → `mobile`), `desktop` otherwise.
  - `windowTitle`: text of the browser window's title bar.
  - `url`: text of the address bar; a web page shows its own URL when missing.
  - `scale`: zoom of the framed content, e.g. `0.5` renders a web page at twice the frame size, shrunk to fit.

```md
---
layout: media-right
media: /screenshot.png
window: true
type: mobile
url: example.com
---

## Title
- Point
```

A media can also be placed anywhere in a slide's content with the same sources: `<MediaEl src="qr:https://…"/>`.

### Utility layouts

- `404` / `error`: used internally by Slidev.

### QR codes

A QR code is a `<MediaEl>` written in the slide content, with the same sources as `media`, so a generated code can
be swapped for an image when needed:

```md
::qr-code::
<MediaEl src="qr:https://example.com"/>   <!-- generated, in the title color -->
<MediaEl src="/qr.png"/>                  <!-- or an image from the deck's img/ -->
```

- **Cover**: the template's `::qr-code::` block encodes the deck's `url`:
  `<MediaEl :src="'qr:' + $frontmatter.url"/>`.
- **End**: the shared `src/common/end.md` holds `<MediaEl :src="$frontmatter.qrCode"/>`. Its content can't be edited
  per talk, so its value is the one QR code set in frontmatter, on the `src:` slide (default
  `qr:https://francoiseoche.fr`):

```md
---
src: ../../../src/common/end.md
qrCode: qr:https://example.com/feedback
---
```

## Commands

| Command                                       | Description                                         |
|-----------------------------------------------|-----------------------------------------------------|
| `npm run new -- <pro\|misc>/<slug> "Title"`    | Create a talk from `talks/slides.example.md`        |
| `pnpm dev [<slug>]`                           | Serve one talk (picker if no slug)                  |
| `pnpm build [<slug>]`                         | Build the website (or one talk) into `dist/`        |
| `pnpm export <slug>`                          | Export one talk to PDF in its `export/` folder      |
| `npm run export:docs [-- --deck <slug>]`      | Export decks to Markdown, HTML handout and PDF      |
| `pnpm prettier --write "**/*.md"`             | Format Markdown (Slidev parser)                     |

## Website

Every push to `main` builds every talk and deploys them to GitHub Pages
(`.github/workflows/pages.yml`): **https://feoche.github.io/slides/**.

- **Talk URLs**: each talk is online at `/slides/<slug>/` (its folder name, without `pro/` or `misc/`, so two
  talks can't share a folder name), with speaker notes. Slide URLs (`…/7`, `…/presenter/7`) can be shared and
  reloaded: `dist/404.html` sends them to their deck (`scripts/lib/spa-fallback.js`).
- **Home page**: clickable cards to the talks listed in **`talks/home.yaml`** (folder names), in its order. Every
  talk is listed there: remove one to keep it off the home page (it stays online at its URL). Each
  card is made of the deck's headmatter: `title`, `event`, `date` (month and year), `summary` (default: `info`)
  and `keywords` as badges.
- **Style**: the home and 404 pages follow https://francoiseoche.fr/ (`scripts/lib/site.css`: its colors,
  Albert Sans / Outfit fonts, cards and tags), dark mode included.
- Theme previews (`src/common/`) aren't online; `pnpm build common/showcase` builds one locally.
- Preview the site as deployed: `pnpm build --base /slides/`, then serve `dist/` under `/slides/`.

## Document export (Pandoc)

```bash
npm run export:docs                            # all decks
npm run export:docs -- --deck misc/speedrun    # one deck
npm run export:docs -- --verbose               # print pandoc commands
```

Outputs land in `<deck>/export/`. Defaults come from `src/_templates/default-meta.yaml`, overridden by the deck's
`meta.yaml`. Without a LaTeX engine, Markdown and HTML are still produced and PDF is skipped.

## Theme

Design tokens (colors, fonts, spacing) live in `src/theme/styles/tokens.css`. Primary color `#00574a`, fonts
Albert Sans (body), Outfit (headings) and Cascadia Code (code). Light and dark schemes are both supported.
